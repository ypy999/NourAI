## 3. Why exact reproduction is impossible today

| Artifact | Blocker |
| --- | --- |
| QNL `imported.jsonl` | Adds `qnl_metadata` (9 CSV fields), `arabic_script_ratio`, `provenance_id_source`, `document_id_status`. `corpus.importers` treats each ZIP member as plain text and derives none of these. |
| QNL `normalized.jsonl` | Drops `raw_text`, `normalized_text` and `cleaned_text`, while `data.normalization.transform_record` + `canonical_record` always keep them. The transformation cannot be replayed from the file. |
| WTO `imported.jsonl` | The archive is a tab-separated **parallel** corpus. `corpus.importers` would treat each physical line as one record and lose EN/FR alignment, `translation_group_id`, `document_id`, `domain` and segment identity. |
| WTO sample selection | `wto_chunk00_import_validation.json` documents a deterministic domain-stratified sample (124 documents) whose domain mapping and seed are not implemented anywhere in the repository. |
| `splits_v1` | `split_generation.json` records seed `10202` and ratios `0.7/0.15/0.15`, which conflict with the approved configuration (see below). Parent normalized inputs are themselves not reproducible, so identical splits cannot be regenerated. |

The aborted WTO attempts (`.partial`, 1.19 GB) and the `.bin` range fragments are residue; they are not inputs to any import and cannot be regenerated byte-for-byte.

## 5. Rebuilt reproducible path

`corpus/reproducibility.py` provides two operations:

### Audit
```powershell
python -m corpus.reproducibility audit --root .
```
Writes `ARTIFACT_AUDIT.json` / `.md` with per-file size, SHA-256, schema keys, sidecar link, producer verdict and reason.

### Plan (must be READY before any generation)
```powershell
python -m corpus.reproducibility plan --root . --output data/processed/phase10_3 `
  --source tatoeba_cc0 --source qnl_arabic_ocr_v2 --source wto_public_corpus_en_fr --verify-hashes
```
The planner:

- refuses to target the frozen `data/processed/phase10_2` tree or an existing directory;
- requires a provenance sidecar for every raw input and checks `source_id`, `bytes` and `sha256`;
- with `--verify-hashes`, runs the strict download-provenance verifier (URL identity, license identity, SHA-256, and MD5 when recorded);
- refuses to claim readiness for formats whose provenance would be lost:
  - `qnl_arabic_ocr_v2` → `PARTIAL` (needs a QNL adapter for `document_id` + metadata CSV); blocked unless `--allow-partial` is passed explicitly;
  - `wto_public_corpus_en_fr` → `UNSUPPORTED` (needs a parallel-corpus adapter); always blocked.

### Proven on fixtures, not on 13.4 GB
`tests/test_phase10_2_reproducibility.py` proves on synthetic inputs that:

1. `import_source_file` writes a `*.import.json` sidecar containing the source SHA-256 and accepted record count;
2. `normalize_imported_file` keeps the transformation trace;
3. `split_sources` with a fixed seed and fixed ratios produces byte-identical splits across two runs;
4. the audit correctly classifies ad-hoc enrichment, dropped transformation fields, aborted attempts and raw artifacts.

The real run is **not** started: the plan is blocked by the missing QNL/WTO adapters, exactly as required before spending 13.4 GB of regeneration.
